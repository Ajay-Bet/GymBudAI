# Local curl dataset and rep-end pilot

This workspace advances only the authorized dataset/classifier/browser portions of Sprints 7–9. It does not establish production acceptance, recording review, or deployment. Videos remain local. Extraction dependencies and commands are described in `extract.py --help`; the portable training baseline uses Python 3.10+ standard library, without installing packages in the backend.

The supplied annotations must be audited as actually stored. `annotations.py` accepts UTF-8 BOM CSV and rejects ZIP/Apple Numbers files mislabeled `.csv`. Preserve the source and explicitly convert to a separate local CSV. Install optional pinned `ml/requirements-annotations.txt` in an isolated environment, then run `python -m ml.convert_numbers --source backend/annotations.csv --output ml/outputs/annotations-frame.csv`; conversion writes source checksum and provenance beside the output and preserves the original. Original labels/severity/notes are retained. `swinging` is a composite observed issue (torso and/or upper-arm/shoulder motion), not evidence of a specific mechanism. Severity `normal` never implies good form. `incomplete_rom` maps to `incomplete-rom`; no other semantic mapping is inferred.

Timestamp intervals are `[start_seconds,end_seconds)`. Frame CSV uses `start_frame,end_frame`. The user confirmed on 2026-10-04 that indexes are zero-based and the end frame is included. Map those indexes through each video's decoded presentation timestamps, never `index/fps` and never a sampled extraction index. Inclusive end uses the next frame PTS as the exclusive limit. An index outside the decoded sequence is reported as `frame_index_out_of_range` and is not truncated. An inclusive end on the final decoded frame is `inclusive_end_needs_following_timestamp` until that next PTS exists. `N/A` is `missing_end_frame` and stays out of bounded tasks. Ordinary unannotated intervals are unknown.

Create a metadata JSON keyed by recording ID with confirmed `participantId`, `view` (`side` for this pilot), anatomical `arm` (`left`/`right`), `reviewStatus` (`independently-reviewed` only when established), and `assessedLabels` (issues the reviewer actually assessed, e.g. `["swinging"]`). Do not infer these from filenames. A `no_issue_observed` row provides a negative only for explicitly assessed labels. Coexisting positive labels use `|`; other targets remain null. Rep completion remains separate from issue targets.

`dataset.py` accepts exact human-bounded shared rep aggregates in JSON: `featureOrder`, `units`, `reps` (`recordingId,startMs,endMs,features` vector), optional original `frame_times`, `frame_basis`, `end_inclusive`. Aggregate features using `frontend/src/ml/repFeatures.js` against `ml/outputs/measurements/<recording>/<arm>/frames.jsonl`. Select half-open observation windows before aggregation. Pass `--measurements ml/outputs/measurements` to dataset construction to invoke the shared browser aggregator directly after metadata/conventions are confirmed; its feature window closes at the last included observed timestamp, matching browser rep completion. Never match automatic candidate reps to annotations by ordinal number or label every frame using a rep target. Candidate reps and clip-wide labels are not automatically training examples. `rep-end-v1` remains the calibration-relative vector: duration ms; min/max elbow flexion degrees; observed ROM degrees; maximum absolute torso deviation degrees; maximum absolute upper-arm drift degrees; median absolute elbow angular velocity degrees/second; valid form coverage fraction. It needs a ready calibration baseline, so clips with no relaxed hold produce no v1 rows.

`rep-end-v2` is the experimental rep-end vector used when a live calibration hold is absent: the same duration, flexion, ROM and velocity fields, plus torso and upper-arm angle ranges inside the human window, and geometry coverage. It reads smoothed angles from frames that already pass active tracking and the side-orientation gate. It does not read or relax the calibration baseline. Browser inference calls the same function when the analyzer completes a rep, so live predictions still require that calibration hold and the existing tracking gates. Both vectors abstain on missing values. Full-window statistics are rep-end features only.

The annotation command above already passes the confirmed zero-based inclusive convention and verified frame times. All generated outputs are local/ignored. A blocked training attempt exits 2 and writes `training-report.json`; it never creates a fake classifier. Synthetic arithmetic parity fixture `ml/tests/fixtures/parity.json` is explicitly a test fixture, not a trained model or accuracy evidence. If blocked in a directory containing an earlier successful artifact, that artifact is historical: the current report takes precedence; use fresh versioned output directories to avoid ambiguity.

Training groups participants before preprocessing; all clips of a known participant remain together. At least three groups are necessary, not sufficient for credible evaluation. `--allow-recording-split` permits grouped recordings only as an experimental pilot and still keeps known participants together. Unknown overlap is documented. Seed 2026 partitions groups into test, validation and training; no frame shuffle. Means/population standard deviations fit training data only; constant columns use scale 1. Independent logistic heads use 1200 full-batch gradient steps, learning rate .1, L2 .01 on weights, no class weighting. Unknown targets are masked per head. Train and validation both require positive and negative support per exported head. Validation chooses thresholds on a declared .05–.95 grid maximizing F1, then closest to .5. Test never selects preprocessing, weights or thresholds. `--fixed-threshold-pilot` is only for a recording split that cannot fill three partitions with both classes. It keeps the threshold at the predeclared value 0.5, fits preprocessing on the training groups only, and evaluates the other half. It is not a tuned or participant-independent result. `--allow-unreviewed-experimental` accepts the supplied table as `supplied-human-unreviewed`; it does not mark those labels independently reviewed. `--allow-derived-arm` may select the arm with greater elbow range and records that choice as unconfirmed.

Evaluation reports per-label support/positives/negatives, precision/recall/F1 and false positive/negative counts, missing assessment, split class coverage and same-row rules comparison where available. Undefined metrics are null. Hybrid policy and within-rep cue rate/delay remain unassessed; this rep-end pilot does not establish live performance or calibrated probabilities. Front/oblique views stay unsupported.
